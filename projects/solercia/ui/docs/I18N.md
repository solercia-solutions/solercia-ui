# i18n — `@solercia/ui`

The design system is **i18n-engine-agnostic**. Components never import Transloco,
ngx-translate, or `@angular/localize`. They depend only on a tiny injection
contract, `SOL_I18N`, that the host implements with whatever engine it already
uses. The pattern mirrors Angular Material's `*Intl` services.

```ts
import { SOL_I18N, type SolI18n } from '@solercia/ui';
```

---

## 1. The `SolI18n` contract

Defined in `lib/i18n/sol-i18n.ts`:

```ts
interface SolI18n {
  /** Active language as a reactive signal. */
  readonly activeLang: Signal<string>;

  /** Synchronous translation. Returns the key itself when it is missing. */
  translate(key: string, params?: Record<string, unknown>): string;

  /** Reactive translation: the returned signal recomputes when the language changes. */
  t(key: string, params?: Record<string, unknown>): Signal<string>;

  /** Translate several keys at once, in the same order. */
  tMany(keys: string[]): Signal<string[]>;
}
```

| Member | Returns | Use for |
|---|---|---|
| `activeLang` | `Signal<string>` | Reacting to language changes (e.g. a language selector). |
| `translate(key, params?)` | `string` | One-off synchronous lookups (imperative code). Missing key → returns the key. |
| `t(key, params?)` | `Signal<string>` | Template bindings that must re-render on language change. Call inside an injection context (field initializer / constructor). |
| `tMany(keys)` | `Signal<string[]>` | Static ordered lists (e.g. stepper labels). |

The token and its **identity default**:

```ts
export function createIdentitySolI18n(): SolI18n {
  return {
    activeLang: signal('es-CO'),
    translate: (key) => key,          // returns the key unchanged
    t: (key) => signal(key),
    tMany: (keys) => signal(keys),
  };
}

export const SOL_I18N = new InjectionToken<SolI18n>('SOL_I18N', {
  providedIn: 'root',
  factory: createIdentitySolI18n,      // works out of the box
});
```

Because the token is `providedIn: 'root'` with the identity factory, the library
**works with zero host wiring**: unresolved keys fall through to each component's
built-in default copy. A host provides a real engine to translate them.

## 2. Providing an engine

### Option A — Transloco (real `boki-front` example)

The host wraps its engine in a facade that satisfies `SolI18n`, then binds it to
the token with `useExisting`.

Facade (`src/shared/i18n/i18n.service.ts`):

```ts
import { Injectable, Signal, inject } from '@angular/core';
import { TranslocoService, translateSignal } from '@jsverse/transloco';

@Injectable({ providedIn: 'root' })
export class I18nService {
  private readonly transloco = inject(TranslocoService);

  readonly activeLang: Signal<string> = this.transloco.activeLang;

  translate(key: string, params?: Record<string, unknown>): string {
    return this.transloco.translate(key, params);
  }
  t(key: string, params?: Record<string, unknown>): Signal<string> {
    return translateSignal(key, params);
  }
  tMany(keys: string[]): Signal<string[]> {
    return translateSignal(keys);
  }
}
```

Wiring (`src/app/app.config.ts`):

```ts
import { SOL_I18N } from '@solercia/ui';
import { provideI18n, I18nService } from '@shared/i18n';

providers: [
  ...provideI18n(),   // host's Transloco setup + APP_INITIALIZER preloading the default lang
  // Route @solercia/ui components through the host's engine.
  { provide: SOL_I18N, useExisting: I18nService },
];
```

`I18nService` structurally implements `SolI18n` (same members), so `useExisting`
is enough — no adapter class needed.

### Option B — ngx-translate (or any other engine)

Write a small facade that adapts the engine's API to the four `SolI18n` members
and provide it the same way:

```ts
import { Injectable, Signal, signal, inject } from '@angular/core';
import { TranslateService } from '@ngx-translate/core';
import { toSignal } from '@angular/core/rxjs-interop';

@Injectable({ providedIn: 'root' })
export class NgxSolI18n /* implements SolI18n */ {
  private readonly tr = inject(TranslateService);
  readonly activeLang = toSignal(this.tr.onLangChange.pipe(/* map to lang */),
    { initialValue: this.tr.currentLang });

  translate(key: string, params?: Record<string, unknown>): string {
    return this.tr.instant(key, params);
  }
  t(key: string, params?: Record<string, unknown>): Signal<string> {
    // recompute on language change; simplest correct form is toSignal over stream$
    return signal(this.tr.instant(key, params));
  }
  tMany(keys: string[]): Signal<string[]> {
    return signal(keys.map((k) => this.tr.instant(k)));
  }
}

// providers
{ provide: SOL_I18N, useExisting: NgxSolI18n }
```

> The reactive members (`activeLang`, `t`, `tMany`) must recompute when the
> language changes. With Transloco this comes for free via `translateSignal` +
> `reRenderOnLangChange`. With other engines, bridge the engine's
> language-change stream into a signal (`toSignal`).

### Option C — no engine (identity default)

Provide nothing. `SOL_I18N` resolves to `createIdentitySolI18n()`:
`activeLang` is `es-CO`, and every lookup returns the key unchanged, so
components render their built-in default copy. Useful for demos, Storybook, or
hosts that do not need translation.
