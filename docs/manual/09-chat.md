# Chat

```ts
import { ApplicationConfig } from '@angular/core';
import { provideSolerciaChat } from '@solercia/chat';

export const appConfig: ApplicationConfig = {
  providers: [
    provideSolerciaChat({
      apiBase: '/support/api',
      textos: { titulo: 'Help' },
    }),
  ],
};
```

```html
<sol-chat-flotante
  [(abierto)]="chatOpen"
  [lanzador]="true"
  [contexto]="{ ruta: '/contracts/payment-reports', titulo: 'Payment reports' }"
  titulo="Assistant"
/>
```

`@solercia/chat` is an embeddable assistant: answers streamed over Server-Sent Events, the current
screen as optional context, cited sources, conversation history and a floating bubble. It ships the
user interface only; the service that answers is separate and implements the API contract below.

## Why a separate package

- Its only peer dependencies are `@angular/core` and `@angular/common` (22.1), so it can be added to
  applications that do not use `@solercia/ui` yet.
- It reads the same `--sol-*` tokens, so inside a Solercia application it follows the tenant theme and
  dark mode without configuration, and it falls back to its own light and dark palette elsewhere.
- It streams with `fetch` and `ReadableStream`; host `HttpClient` interceptors are not involved. Send
  any header the API needs (XSRF token, authorization) through `cabeceras()`.

> **Naming note.** The public API uses Spanish identifiers (`contexto`, `titulo`, `cabeceras`) because
> the package was born in Spanish-speaking public-sector projects. They are stable API; the English
> meaning is given below.

## Configuration

`provideSolerciaChat(config?)` registers `SOLERCIA_CHAT_CONFIG`. To keep the package out of the initial
bundle, provide the configuration in the component that uses the chat instead.

| Field | Meaning | Default |
| --- | --- | --- |
| `apiBase` | Base URL of the chat API | `'/api'` |
| `credentials` | `fetch` credentials mode | `'include'` |
| `cabeceras` | Extra request headers, evaluated per request | none |
| `textos` | Override any visible text (`Partial<TextosChat>`) | `TEXTOS_CHAT_POR_DEFECTO`, Spanish |
| `maxCaracteres` | Maximum question length | `1000` |
| `persistir` | Keep the conversation in `sessionStorage` | `true` |
| `claveAlmacen` | Storage key; share it to resume a conversation across screens | `'solercia-chat'` |
| `maxHistorial` | Previous turns sent to the API | `10` |
| `historial` | Enable the saved-conversations list | `false` |

Default texts are Colombian Spanish; pass `textos` to localize.

## Components

| Component | Use it for | Key inputs and outputs |
| --- | --- | --- |
| `<sol-chat>` | An inline chat in a page or side panel | `contexto` (screen), `titulo` (title), `subtitulo` (subtitle), `sugerencias` (up to 4 suggested questions), `compacto` (dense), `contraido` (collapsed), `historial`; outputs `respuesta` (answer) and `error` |
| `<sol-chat-flotante>` | A floating bubble in the bottom-right corner | `abierto` (open, two-way), `contraido` (minimized, two-way), `lanzador` (launcher button), `conModoCompleto` (full-screen button); outputs `modoCompleto`, `cerrado`, `respuesta`, `error` |

Only one chat is open at a time: while an inline `<sol-chat>` is mounted, the bubble stays hidden. The
context chip can be removed and attached again by the user and travels with the request only while
attached.

## API contract

`POST {apiBase}/chat` with `Accept: text/event-stream`:

```json
{
  "pregunta": "How do I submit a payment report?",
  "historial": [{ "rol": "usuario", "texto": "…" }, { "rol": "asistente", "texto": "…" }],
  "conversacionId": "uuid generated by the browser",
  "contexto": { "ruta": "/contracts/payment-reports", "titulo": "Payment reports" }
}
```

| Server-Sent Event | Data |
| --- | --- |
| `fuentes` | Sources retrieved for the answer |
| `cola` | Queue position: `posicion`, `esperaEstimadaSegundos` |
| `fragmento` | Answer chunk: `texto` |
| `fin` | Final answer: `estado`, `respuesta`, `citas`, `documentos`, `casos` |
| `error` | Error envelope with `status.appDesc` and `status.appCode` |

With `historial: true` the chat also calls `GET`, `PATCH` and `DELETE` on `{apiBase}/conversaciones`.
The full contract, including history payloads, is in the
[`@solercia/chat` README](https://github.com/solercia-solutions/solercia-chat#api-contract).

## Rules

1. Configure once with `provideSolerciaChat`; do not wrap the API in `HttpClient`.
2. Customize through inputs and `textos`; do not fork templates or style internals.
3. A backend built for the chat implements the API contract exactly, including the event names.
4. Markdown in answers is rendered as an Angular node tree, never through `innerHTML`.
